## AF-001 · 2026-09-14 · Пропущенный `name:` в docker-compose.yml

**Контекст:** генерация `infra/docker-compose.yml` для недели 1. Ассистент
сверил свой вариант с эталонным из `docs/plan/weeks/week-01-guide.md` и
перечислил отличия.

**Что было предложено:** compose-файл без верхнеуровневого `name:`.
Отличие от эталона было замечено, но оценено дословно так: «это только
смена префикса имён контейнеров, не критично».

**Почему неверно:** без `name:` Compose берёт имя проекта из имени
каталога, где лежит compose-файл, — то есть `infra`. Это не косметика:
имя проекта определяет идентичность стека и префикс имён томов
(`infra_postgres_data`). Следствия: любой другой репозиторий с папкой
`infra/` получает то же имя проекта и те же тома; а проверка «чистый
клон → `make up`» становится недействительной — Compose видит уже
запущенный проект `infra` и переиспользует его контейнеры и тома
вместо создания новых, то есть init-скрипты Postgres не выполняются
и проверка ничего не проверяет.

**Как обнаружил:** процедурой чистой проверки из DoD недели 1 —
`git clone` в отдельный каталог, затем `docker compose config` перед
запуском. Ни тесты, ни линтеры этот класс ошибки не ловят.

**Класс ошибки:** прочее — неверная оценка значимости отличия от
эталона. Код работал, ошибка проявлялась только в свойствах
изоляции окружения.

**Правило в CLAUDE.md:** не требуется. Общий вывод для себя: когда
ассистент отмечает расхождение с эталоном и сам же объявляет его
некритичным — это место для проверки, а не для доверия.
