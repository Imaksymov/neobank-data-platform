# Контекст проекта: данные и бюджет

## Датасеты

Только публичные и синтетические. Корпоративные данные не используются.

| Датасет | Что даёт | Где взять |
|---|---|---|
| **PKDD'99 Berka** | Ядро проекта: чешский банк, 5300 клиентов, 4500 счетов, 1M транзакций, кредиты, карты, демография районов. Реальная банковская схема, 4 года истории | Kaggle, архив PKDD'99 |
| **PaySim** | 6.3M синтетических платёжных событий с метками фрода — для стриминга и объёма | Kaggle |
| **Lending Club Loan Data** | 2.2M кредитов с исходом (default/paid) — основа PD-модели и IFRS 9 | Kaggle |
| **API НБУ** | Курсы валют и учётная ставка. Живой инкрементальный источник, обновляется ежедневно, без ключа | bank.gov.ua/NBUStatService |
| **ECB Data Portal** | Макропеременные для forward-looking компонента ECL | ECB SDW API |
| **Faker / SDV** | Догенерация PII (ФИО, адреса, документы) для отработки маскирования и GDPR | pip |

**Важно:** Berka покрывает 1993–1998 гг. Скрипт сдвига дат проецирует
историю на 2021–2026. Полдня работы, но это делает проект живым:
появляются инкрементальные модели, партиционирование по датам,
осмысленный «вчерашний батч».

## Бюджет на облако

Стратегия — разработка локально, облачные спринты точечно.

- **Локально (0 ₴):** DuckDB + dbt + Docker Compose. 90% работы здесь.
- **BigQuery free tier:** 10 ГБ хранения + 1 ТБ запросов в месяц,
  бессрочно. Для «настоящего облачного DWH».
- **Snowflake trial:** $400 / 30 дней. Один сфокусированный спринт.
- **AWS:** S3 + Lambda + Glue в пределах free tier. Redshift Serverless
  включать только на 2–3 недели под сертификацию, обязательно
  с budget alert на $20.
